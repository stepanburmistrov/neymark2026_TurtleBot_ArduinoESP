# Протокол робота

## Команды

| Команда | Назначение |
|---|---|
| `PING` | Проверка связи |
| `GET` | Немедленно запросить состояние |
| `VEL linear_mm_s angular_mrad_s` | Задать линейную и угловую скорость |
| `STOP` | Остановить оба мотора |
| `SERVO angle_deg` | Повернуть сервопривод |
| `RESET_ODOM` | Принять текущее положение за `(0, 0, 0)` |

Примеры:

```text
VEL 250 0       движение вперёд
VEL 0 3500      поворот влево
VEL 0 -3500     поворот вправо
STOP            остановка
```

Каждая команда заканчивается символом перевода строки `\n`.

## Телеметрия

Arduino передаёт строку:

```text
TEL x y theta v w encL encR lineL lineR ir servo
```

| Поле | Содержание | Единица |
|---|---|---|
| `x`, `y` | Координаты центра робота | мм |
| `theta` | Ориентация робота | мрад |
| `v` | Измеренная линейная скорость | мм/с |
| `w` | Измеренная угловая скорость | мрад/с |
| `encL`, `encR` | Счётчики энкодеров | тики |
| `lineL`, `lineR` | Аналоговые значения датчиков линии | 0…1023 |
| `ir` | Расстояние по ИК-дальномеру | см |
| `servo` | Текущий угол сервопривода | градусы |

В строке ровно 12 элементов: слово `TEL` и 11 целых чисел.

## Почему нельзя разбирать TCP по вызовам `recv()`

TCP передаёт поток байтов, а не отдельные сообщения. Одна строка может прийти частями, а несколько строк — одним пакетом. Поэтому программы накапливают байты в буфере и выделяют данные только по символу `\n`.

Пример квадратного маршрута:


Все введённые координаты являются **абсолютными координатами в одной системе одометрии**, а не смещениями относительно текущего положения.

Дополнительные команды:

| Команда | Действие |
|---|---|
| `pose` | Показать текущие координаты и угол |
| `reset` | Принять текущее положение за `(0, 0, 0)` |
| `stop` | Немедленно отправить `STOP` |
| `exit` | Остановить робота и завершить программу |

### 4.1. Ошибка положения

Пусть текущая координата робота — `(x, y)`, а новая цель — `(xₜ, yₜ)`.

```text
Δx = xₜ − x
Δy = yₜ − y
```

Расстояние до цели:

```text
ρ = √(Δx² + Δy²)
```

### 4.2. Направление на новую точку

Перед началом каждого отрезка вычисляется направление от текущего положения к новой точке:

```text
θцели = atan2(Δy, Δx)
```

Ошибка курса:

```text
eθ = θцели − θробота
```

Угол приводится к диапазону от `−π` до `+π`, чтобы робот выбирал кратчайший поворот.

### 4.3. Две отдельные фазы движения

В этой версии поворот и движение вперёд намеренно разделены.

**Фаза 1 — поворот.** Робот стоит на месте и разворачивается к новой точке. Угловая скорость уменьшается вместе с ошибкой направления:

```text
ω = K · eθ
```

**Фаза 2 — прямой отрезок.** После выравнивания направление фиксируется. Робот едет с постоянной линейной скоростью:

```text
VEL 220 0
```

Во время этого отрезка угловая скорость всегда равна нулю. Робот не подруливает, не переключается обратно в режим поворота и поэтому не должен дёргаться. После достижения точки дополнительного поворота также нет.

```mermaid
flowchart TD
    I[Ввести X и Y в консоли] --> P[Получить текущие X, Y и θ]
    P --> H[Вычислить направление на точку]
    H --> R[Повернуться на месте]
    R --> L[Зафиксировать прямой отрезок]
    L --> F[Ехать с постоянной скоростью<br/>VEL 220 0]
    F --> D{Отрезок пройден?}
    D -->|нет| F
    D -->|да| S[STOP]
    S --> I
```

### 4.4. Как определяется окончание отрезка

После поворота программа запоминает начальную точку отрезка и единичный вектор его направления. По текущей одометрии вычисляется, насколько далеко робот продвинулся вдоль этого вектора.

```text
progress = (x − x₀) · ux + (y − y₀) · uy
```

Остановка выполняется, когда робот оказался в допустимой близости от цели либо прошёл почти всю расчётную длину отрезка. Такой критерий не позволяет роботу бесконечно продолжать движение, если из-за небольшой механической погрешности он прошёл рядом с точкой.

### 4.5. Важное ограничение

Во время прямого движения курс намеренно не корректируется. Поэтому точность зависит от:

- одинаковой скорости колёс;
- качества калибровки;
- сцепления с поверхностью;
- точности одометрии;
- отсутствия пробуксовки.

Этот пример нужен для наглядного построения маршрута из отдельных команд: **повернуться — проехать прямой отрезок — остановиться — принять следующую точку**.

# Часть III. HSV, маски и контуры

## 9. Почему используется HSV

Код: [`09_hsv_tuner.py`](09_hsv_tuner/09_hsv_tuner.py)

В BGR одновременно меняются и цвет, и яркость. Например, один красный предмет при ярком и слабом освещении может иметь очень разные значения каналов.

HSV разделяет признаки:

| Канал | Смысл |
|---|---|
| `H` — Hue | Цветовой тон: красный, жёлтый, зелёный, синий |
| `S` — Saturation | Насыщенность цвета |
| `V` — Value | Яркость |

В OpenCV диапазоны отличаются от привычной цветовой модели:

```text
H: 0…179
S: 0…255
V: 0…255
```

Цветовая маска строится так:

```python
hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv, lower, upper)
```

В маске:

- `255` — пиксель входит в заданный диапазон;
- `0` — пиксель не входит.

Ползунки позволяют подобрать границы по реальному объекту и реальному освещению.

### Почему для красного нужны два диапазона

Шкала оттенка замкнута в кольцо. Красный находится одновременно около начала и конца шкалы `H`:

```text
0 … 10      первый красный диапазон
170 … 179   второй красный диапазон
```

Поэтому создаются две маски и объединяются логической операцией OR:

```python
mask = cv2.bitwise_or(mask_1, mask_2)
```

## 10–12. Поиск цветных объектов

- Красный: [`10_detect_red.py`](10_detect_red/10_detect_red.py)
- Синий: [`11_detect_blue.py`](11_detect_blue/11_detect_blue.py)
- Зелёный: [`12_detect_green.py`](12_detect_green/12_detect_green.py)

Общий конвейер:

```mermaid
flowchart LR
    A[BGR-кадр] --> B[Преобразование в HSV]
    B --> C[Цветовая маска]
    C --> D[Морфологическая очистка]
    D --> E[Поиск контуров]
    E --> F[Фильтр по площади]
    F --> G[boundingRect и координаты центра]
```

### Что такое контур

Контур — последовательность точек, описывающих границу связной белой области бинарной маски.

```python
contours, _ = cv2.findContours(
    mask,
    cv2.RETR_EXTERNAL,
    cv2.CHAIN_APPROX_SIMPLE,
)
```

- `RETR_EXTERNAL` возвращает внешние границы объектов;
- `CHAIN_APPROX_SIMPLE` сокращает число точек на прямых участках.

Мелкие области отбрасываются по площади:

```python
area = cv2.contourArea(contour)
if area < MIN_CONTOUR_AREA:
    continue
```

### Что делает `boundingRect`

```python
x, y, width, height = cv2.boundingRect(contour)
```

Функция возвращает наименьший прямоугольник, стороны которого параллельны осям изображения и который полностью охватывает контур.

Центр прямоугольника:

```text
center_x = x + width / 2
center_y = y + height / 2
```

Эти координаты можно использовать как положение объекта в кадре.

## 13. Один маркер и четыре вершины

Код: [`13_aruco_single.py`](13_aruco_single/13_aruco_single.py)

Детектор возвращает:

```python
corners, ids, rejected = detector.detectMarkers(frame)
```

Для каждого маркера `corners` содержит четыре точки в согласованном порядке:

```text
0 — верхний левый угол маркера
1 — верхний правый
2 — нижний правый
3 — нижний левый
```

Порядок задаётся относительно ориентации самого маркера, поэтому по нему можно определить направление.

## 14. Центр и угол маркера

Код: [`14_aruco_center_angle.py`](14_aruco_center_angle/14_aruco_center_angle.py)

Центр вычисляется как среднее четырёх вершин:

```text
C = (P₀ + P₁ + P₂ + P₃) / 4
```

Середина верхней стороны:

```text
F = (P₀ + P₁) / 2
```

Вектор направления:

```text
h = F − C
```

В изображении начало координат находится слева сверху, а `Y` растёт вниз. Перед вычислением привычного математического угла знак вертикальной компоненты меняется:

```text
angle = atan2(−hᵧ, hₓ)
```

Массив `ids` сопоставляется с массивом `corners`:

```python
for marker_corners, marker_id in zip(corners, ids):

```

# 16. Щелчок по изображению задаёт цель роботу

Код: [`16_click_to_drive.py`](16_click_to_drive/16_click_to_drive.py)

На роботе закреплён ArUco-маркер ID `4`. Сторона маркера между вершинами `P₀` и `P₁` должна быть направлена вперёд по корпусу.

Программа объединяет всё, что было сделано раньше:

1. получает изображение с камеры;
2. находит ArUco-маркер робота;
3. определяет центр робота;
4. определяет направление робота;
5. получает точку, выбранную мышью;
6. вычисляет расстояние до точки;
7. вычисляет, в какую сторону нужно повернуть;
8. отправляет роботу команду поворота, движения или остановки.

Ниже — демонстрация работы: щелчок по изображению задаёт цель, и робот едет к выбранной точке.

![Демонстрация управления роботом по клику](resources/media/click_to_drive_demo.gif)

Управление:

| Действие | Результат |
|---|---|
| Левая кнопка мыши | Задать новую цель |
| Правая кнопка мыши | Удалить цель и остановиться |
| `Space` | Удалить цель и остановиться |
| `Esc` | Остановиться и завершить программу |

## 16.1. Как программа получает точку щелчка

Сначала создаётся переменная, в которой будет храниться цель:

```python
target_pixel: tuple[int, int] | None = None
```

Она может содержать:

- пару координат `(X, Y)`, если цель уже выбрана;
- значение `None`, если цели пока нет.

Затем окну OpenCV назначается функция обработки мыши:

```python
cv2.setMouseCallback(window, mouse_callback)
```

Это означает: каждый раз, когда пользователь нажимает кнопку мыши над окном, OpenCV вызывает функцию `mouse_callback`.

Функция получает тип события и координаты курсора:

```python
def mouse_callback(
    event: int,
    x: int,
    y: int,
    _flags: int,
    _data: object,
) -> None:
```

Здесь:

- `event` — какое именно событие произошло;
- `x` — горизонтальная координата курсора;
- `y` — вертикальная координата курсора.

При нажатии левой кнопки мыши координаты сохраняются:

```python
if event == cv2.EVENT_LBUTTONDOWN:
    target_pixel = (x, y)
```

Например, щелчок в точке `(700, 300)` создаёт цель:

```text
target_pixel = (700, 300)
```

При нажатии правой кнопки цель удаляется:

```python
elif event == cv2.EVENT_RBUTTONDOWN:
    target_pixel = None
```

Координаты цели относятся не к комнате и не к полу, а именно к текущему изображению:

```text
(0, 0) находится слева сверху
X растёт вправо
Y растёт вниз
```

## 16.2. Как программа находит именно маркер робота

Детектор может увидеть сразу несколько маркеров:

```python
corners, ids, _rejected = detector.detectMarkers(frame)
```

Чтобы быстро получать углы маркера по его ID, создаётся словарь:

```python
markers = {
    int(marker_id): marker_corners
    for marker_corners, marker_id in zip(
        corners,
        ids.flatten(),
    )
}
```

Например, словарь может выглядеть так:

```text
{
    1: углы маркера 1,
    4: углы маркера 4,
    7: углы маркера 7
}
```

Роботом считается маркер с ID `4`:

```python
ROBOT_MARKER_ID = 4
```

Поэтому программа проверяет:

```python
if ROBOT_MARKER_ID not in markers:
    state = "WAIT FOR ROBOT MARKER ID 4"
```

Если маркер `4` не виден, робот не получает команду движения. Команда остаётся равной:

```python
command = "STOP"
```

Это важная защита: робот не должен ехать, если камера потеряла его положение.

Если маркер найден, его углы передаются функции:

```python
robot_center, robot_heading = robot_geometry(
    markers[ROBOT_MARKER_ID]
)
```

Функция должна вернуть:

- `robot_center` — координаты центра робота;
- `robot_heading` — направление передней части робота.

## 16.3. Как вычисляется положение и направление робота

Внутри функции `robot_geometry` углы маркера сначала преобразуются в четыре точки:

```python
points = corners.reshape(4, 2)
```

Центр маркера вычисляется как среднее четырёх вершин:

```python
center = points.mean(axis=0)
```

То есть:

```text
C = (P₀ + P₁ + P₂ + P₃) / 4
```

Этот центр принимается за положение робота в кадре.

Далее находится середина передней стороны маркера:

```python
front = 0.5 * (points[0] + points[1])
```

То есть:

```text
F = (P₀ + P₁) / 2
```

После этого строится вектор от центра к передней стороне:

```python
heading = front - center
```

То есть:

```text
h = F − C
```

Но длина такого вектора зависит от размера маркера на изображении. Если робот находится ближе к камере, маркер выглядит крупнее и вектор получается длиннее. Для расчёта угла длина не нужна — важно только направление.

Поэтому вектор нормализуется:

```python
heading /= max(float(np.linalg.norm(heading)), 1.0)
```

Разберём эту строку по частям.

Сначала вычисляется длина вектора:

```python
np.linalg.norm(heading)
```

Она находится по теореме Пифагора:

```text
|h| = √(hₓ² + hᵧ²)
```

Затем каждая компонента делится на длину:

```text
hₓ = hₓ / |h|
hᵧ = hᵧ / |h|
```

После этого длина вектора становится равной `1`, но направление не меняется. Такой вектор называется **единичным**.

Функция возвращает результат:

```python
return center, heading
```

## 16.4. Как строится вектор от робота к цели

Координаты щелчка преобразуются в массив NumPy:

```python
target = np.array(target_pixel, dtype=np.float32)
```

Теперь известны две точки:

```text
C — центр робота
target — выбранная цель
```

Чтобы получить направление от робота к цели, из координат цели вычитаются координаты робота:

```python
target_vector = target - robot_center
```

В математической записи:

```text
t = target − C
```

Например:

```text
робот: C = (200, 300)
цель:  target = (500, 200)
```

Тогда:

```text
t = (500 − 200, 200 − 300)
t = (300, −100)
```

Это означает:

- до цели нужно сместиться на `300` пикселей вправо;
- до цели нужно сместиться на `100` пикселей вверх, поэтому изменение `Y` отрицательное.

Длина вектора показывает расстояние от робота до цели:

```python
distance = float(np.linalg.norm(target_vector))
```

То есть:

```text
distance = √(tₓ² + tᵧ²)
```

Это расстояние измеряется в пикселях.

Если расстояние меньше заданного допуска:

```python
if distance <= TARGET_TOLERANCE_PX:
```

цель считается достигнутой. Робот останавливается:

```python
command = "STOP"
state = "TARGET REACHED"
```

Допуск нужен потому, что попасть ровно в один пиксель практически невозможно. Робот имеет размеры, инерцию, колёса могут немного проскальзывать, а координаты маркера слегка меняются от кадра к кадру.

## 16.5. Как вычисляется ошибка направления

Теперь известно:

- куда смотрит робот — вектор `robot_heading`;
- где находится цель — вектор `target_vector`.

Нужно определить угол между этими двумя направлениями.

Функция вызывается так:

```python
angle_error = signed_angle(robot_heading, target_vector)
```

Слово `signed` означает «со знаком». Результат должен сообщить не только величину ошибки, но и сторону поворота:

- положительный угол — поворачивать влево;
- отрицательный угол — поворачивать вправо;
- угол около нуля — робот уже смотрит на цель.

### 16.5.1. Переход от координат изображения к математическим координатам

В изображении `Y` растёт вниз, поэтому вертикальные компоненты разворачиваются:

```python
hx, hy = float(heading[0]), -float(heading[1])
tx, ty = float(target_vector[0]), -float(target_vector[1])
```

Здесь:

```text
(hx, hy) — направление робота
(tx, ty) — направление на цель
```

Минус перед вертикальными компонентами нужен, чтобы считать углы в обычной системе, где `Y` направлена вверх.

### 16.5.2. Зачем нужно скалярное произведение

Скалярное произведение вычисляется так:

```python
dot = hx * tx + hy * ty
```

То есть:

```text
dot = hₓtₓ + hᵧtᵧ
```

Оно помогает понять, насколько два вектора направлены в одну сторону:

- `dot > 0` — цель в основном впереди;
- `dot = 0` — цель примерно сбоку, угол около `90°`;
- `dot < 0` — цель находится позади.

Одного скалярного произведения недостаточно: оно не сообщает, слева находится цель или справа.

### 16.5.3. Зачем нужно псевдоскалярное произведение

Для определения стороны рассчитывается:

```python
cross = hx * ty - hy * tx
```

То есть:

```text
cross = hₓtᵧ − hᵧtₓ
```

В двумерной задаче знак `cross` показывает сторону поворота:

- `cross > 0` — цель слева от направления робота;
- `cross < 0` — цель справа;
- `cross = 0` — цель лежит на той же прямой.

### 16.5.4. Почему используется atan2

Угол вычисляется так:

```python
return math.atan2(cross, dot)
```

Функция `atan2` получает сразу две величины:

- `cross` отвечает за сторону поворота;
- `dot` помогает понять, находится цель впереди, сбоку или сзади.

Поэтому `atan2(cross, dot)` может вернуть полный угол от `−180°` до `180°`.

Примеры:

| Положение цели относительно робота | Ошибка |
|---|---:|
| прямо впереди | около `0°` |
| слева | положительная |
| справа | отрицательная |
| точно сзади | около `180°` или `−180°` |

На экране ошибка переводится в градусы:

```python
math.degrees(angle_error)
```

Но для сравнения в программе используется значение в радианах:

```python
elif abs(angle_error) > ANGLE_TOLERANCE_RAD:
```

Функция `abs` убирает знак и оставляет величину ошибки. Если робот отклонён от цели больше чем на допустимые `10°`, сначала выполняется поворот.

Знак ошибки выбирает направление вращения:

```python
angular = (
    ANGULAR_SPEED_MRAD_S
    if angle_error > 0
    else -ANGULAR_SPEED_MRAD_S
)
```

То есть:

- ошибка положительная — отправляется положительная угловая скорость;
- ошибка отрицательная — отправляется отрицательная угловая скорость.

Команда поворота выглядит так:

```python
command = f"VEL 0 {angular}"
```

Первый ноль означает, что линейная скорость равна нулю: робот поворачивается на месте.

Когда ошибка становится достаточно маленькой, программа отправляет движение вперёд:

```python
command = f"VEL {LINEAR_SPEED_MM_S} 0"
```

Здесь:

- `LINEAR_SPEED_MM_S` — скорость движения вперёд;
- последний ноль — отсутствие поворота.

## 16.6. Алгоритм движения

```text
расстояние меньше допуска
        ↓
       STOP

ошибка угла больше допуска
        ↓
поворот на месте к цели

угол выровнен, цель ещё далеко
        ↓
движение вперёд
```

Программа отправляет команду каждые `50 мс`, чтобы Arduino постоянно получала подтверждение управления и не остановилась по watchdog.

## 16.7. Связь с примером 4

Математическая структура полностью повторяет [пример 4 — движение к заданной точке](04_drive_to_point/):

| Пример 4 | Пример 16 |
|---|---|
| Координаты робота приходят из одометрии | Координаты робота определяет камера |
| Единицы — миллиметры | Единицы — пиксели |
| Направление — `theta_mrad` | Направление — верхняя сторона ArUco |
| Цель вводится числами `(X, Y)` | Цель выбирается щелчком |
| Ошибка положения и курса управляет движением | Та же логика управляет движением |

То есть компьютерное зрение не заменяет регулятор. Оно предоставляет другой способ измерить положение робота и цели.

## 16.8. Ограничения метода

- камера должна оставаться неподвижной;
- весь маршрут должен попадать в кадр;
- маркер ID `4` должен быть виден;
- расстояние измеряется в пикселях, а не в миллиметрах;
- перспектива камеры искажает масштаб в разных частях кадра;
- точность зависит от размера маркера, освещения и разрешения.

Для учебного полигона и верхней неподвижной камеры этого достаточно.
