# Интенсив по мобильной робототехнике — Неймарк 2026

![Роботы участников интенсива](images/final/01_robots_ready.jpg)

Репозиторий содержит учебные программы, инструкции, схемы подключения, примеры компьютерного зрения и программные инструменты интенсива по мобильной робототехнике.

Материалы построены по принципу последовательного усложнения: сначала каждый аппаратный узел проверяется отдельной программой, затем измерения объединяются в математическую модель движения, после чего робот получает единый текстовый протокол управления по USB и Wi-Fi. Финальная часть курса посвящена компьютерному зрению, автономной навигации и самостоятельным проектам участников.

За несколько дней участники прошли путь от подключения отдельных датчиков и проверки моторов до систем, в которых компьютер получает изображение с камеры, определяет положение робота и объектов, рассчитывает дальнейшее действие и отправляет команды мобильной платформе.

## Логика курса

### День 1: надёжная аппаратная основа

Каждый компонент подключается и проверяется независимо. Такая последовательность отделяет ошибки монтажа от ошибок алгоритма и позволяет точно определить источник неисправности.

### День 2: переход от импульсов к координатам

Сигналы энкодеров последовательно преобразуются:

```text
тики энкодера
      ↓
путь каждого колеса
      ↓
скорость каждого колеса
      ↓
линейное и угловое перемещение робота
      ↓
координаты X, Y и угол θ
      ↓
телеметрия, карта и удалённое управление
```

Arduino остаётся главным контроллером реального времени: управляет моторами, считывает датчики, рассчитывает скорость и одометрию. ESP32-C3 выполняет транспортную функцию — создаёт Wi-Fi-сеть и передаёт строки протокола между TCP и UART.

### День 3: перенос алгоритмов на компьютер и переход к зрению

Python получает телеметрию робота через TCP, принимает решения и возвращает команды движения. Одни и те же данные используются в нескольких последовательных задачах: движение по линии, остановка перед стеной, работа с одометрией и управление движением.

После этого вводится компьютерное зрение: изображение рассматривается как массив пикселей, изучаются каналы BGR и модель HSV, создаются цветовые маски, находятся контуры и ограничивающие прямоугольники. Финальный пример объединяет камеру, ArUco-маркер и сетевое управление: щелчок по кадру задаёт точку, к которой должен приехать робот.

### День 4: подготовка к индивидуальному проекту

Повторяется протокол обмена с роботом и разбирается набор законченных примеров, которые можно использовать как основу собственного проекта:

- движение к точке, выбранной щелчком мыши;
- маршрут по ArUco-маркерам;
- управление роботом жестами через MediaPipe;
- движение к цветному объекту;
- навигация с обходом препятствий, нарисованных поверх изображения с камеры.

Главная задача дня — показать, как из уже изученных блоков собрать новую систему: получить данные, обработать их, принять решение и передать команду реальному роботу.

### Дни 5–6: собственные проекты

Последние два дня посвящены самостоятельной работе. Участники выбирают собственную задачу, проектируют алгоритм, пишут код, дорабатывают аппаратную часть, тестируют решение и готовят его к защите.

Темы проектов охватывают компьютерное зрение, ArUco-навигацию, управление с игровых устройств, распознавание жестов и лиц, автономное движение, поиск объектов, задачи робототехнических соревнований и олимпиад.

## Что получилось в итоге

К завершению интенсива участники работали уже не с отдельными учебными примерами, а с полноценной архитектурой мобильной робототехнической системы:

```text
датчики и энкодеры
        ↓
      Arduino
        ↓ UART
      ESP32-C3
        ↓ TCP / Wi-Fi
       Python
        ↓
компьютерное зрение
        ↓
алгоритм принятия решения
        ↓
команды движения робота
```

В зависимости от проекта система могла дополняться внешней камерой, ArUco-маркерами, цветовой сегментацией, MediaPipe, нейросетевым распознаванием, игровым контроллером и собственными алгоритмами автономного поведения.

Именно возможность заменить или добавить любой из этих блоков стала основой индивидуальной части курса.

## Принятые единицы измерения

| Величина | Единица |
|---|---|
| Расстояние и координаты | миллиметры, `mm` |
| Линейная скорость | миллиметры в секунду, `mm/s` |
| Угол внутри Arduino | радианы, `rad` |
| Угол в телеметрии | миллирадианы, `mrad` |
| Угловая скорость в командах | миллирадианы в секунду, `mrad/s` |
| Скорость USB Serial | `115200 baud` |
| Скорость UART Arduino ↔ ESP32 | `38400 baud` |

## Общие требования к запуску

- Arduino Nano/Uno или совместимая плата с микроконтроллером ATmega328P.
- Arduino IDE с библиотеками `Servo` и `SoftwareSerial`, входящими в стандартную поставку.
- Python 3 с поддержкой Tkinter.
- Пакет `pyserial` для управления по USB.
- Для примеров компьютерного зрения — зависимости из `requirements.txt` соответствующего дня.
- Общая земля между Arduino, драйвером моторов, датчиками, сервоприводом и ESP32-C3.
- Отключённое питание во время изменения проводки.
